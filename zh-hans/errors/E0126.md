# E0126: 链接失败

程序通过了类型检查，但链接失败了：链接器报告了错误，或者找不到原生库。`nabic check` 在链接之前就停止，所以链接失败只在构建时出现（`nabi build`、`nabi run`、`nabic build`）。常见的原因是在 `extern` 块中声明的函数所在的库没有链接：libc 和 libm 默认会链接，其他库都需要 `#[link]`（[6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-naming-an-external-library)）。检查 `-L` 目录和 `#[link]` 名称。

下面的程序调用了 zlib 函数，却没有链接 zlib：

```nabi norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

在 macOS 上，`nabic build` 输出（有删节；在其他平台上，符号没有前导 `_`）：

```text
   Compiling main (.)
error[E0126]: the link failed:
undefined symbol: _compressBound
>>> referenced by .../module0.o
...
```

`compressBound` 在 zlib 中。链接它：

```nabi
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```
