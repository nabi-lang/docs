# E0126: link failed

The program type-checked, but the link failed: the linker reported an error, or could not find a native library. `nabic check` stops before linking, so a link failure shows up only when building (`nabi build`, `nabi run`, `nabic build`). The usual cause is a function declared in an `extern` block whose library is not linked: libc and libm are linked by default, anything else needs `#[link]` ([6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-naming-an-external-library)). Check the `-L` directories and `#[link]` names.

This program calls a zlib function without linking zlib:

```nabi norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

On macOS, `nabic build` prints (shortened; the symbol has no leading `_` on other platforms):

```text
   Compiling main (.)
error[E0126]: the link failed:
undefined symbol: _compressBound
>>> referenced by .../module0.o
...
```

`compressBound` is in zlib. Link it:

```nabi
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```
