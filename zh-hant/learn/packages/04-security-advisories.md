# 安全性公告

安全性公告說明某個套件的部分版本有漏洞、是哪些版本，以及哪個版本修正了它。登錄庫在 [packages.nabi-lang.org/advisories](https://packages.nabi-lang.org/advisories) 以其他生態系也採用的 [OSV](https://ossf.github.io/osv-schema/) 格式發布安全性公告，`nabi audit` 則用它們檢查你的專案。

## 檢查專案：`nabi audit`

```sh
nabi audit
```

`nabi audit` 會讀取 `nabi.lock`，把其中的每個登錄庫套件（包括工具鏈自帶的官方套件）與其登錄庫的公告比對。對每則適用的公告，它會印出公告的 id 與摘要、公告有提供時的嚴重程度，以及應升級到的版本；接著執行 `nabi update <name>`（第 11 章），或在 `nabi.nabion` 中提高版本需求。路徑相依套件、git 相依套件與原生套件不會檢查，它會說明跳過了哪些。沒有 `nabi.lock` 時，它會先解析出一個。

結束狀態說明檢查的結果：

| 狀態 | 意義 |
|--------|---------|
| 0 | 沒有適用的公告。 |
| 1 | 至少有一則適用。 |
| 2 | 無法檢查：沒有網路也沒有快取的清單、無法讀取鎖定檔，或登錄庫回傳錯誤。訊息會說明是哪一種。 |

清單對每個登錄庫只請求一次，並在 `$NABI_HOME/cache/advisories` 下保留一小時。`--offline` 不論新舊都使用這份副本，取得失敗時也會退回使用它。

| 旗標 | 作用 |
|------|--------|
| `--json` | 每行一個 JSON 物件：每項發現一筆紀錄，每個未檢查的套件一筆，最後是摘要。與 `--format json` 相同。 |
| `--ignore <id>` | 略過一則公告，依它的 id（`NABI-2026-0001`）或別名（`CVE-..`、`GHSA-..`）。可重複使用。 |
| `--offline` | 只使用快取的清單。 |

在 CI 中，請在建置之後執行它；狀態為 1 會讓工作失敗：

```yaml
- run: nabi audit
```

只有在讀過公告、確定你的程式不會執行到受影響的程式碼之後，才略過它；並在旗標旁邊寫明原因。

## 閱讀公告

每則公告在登錄庫上都有一個頁面，受影響版本的頁面會顯示一條連結到它的橫幅。公告會寫明：

- **受影響的版本**：例如「從 0.1.0 起，於 0.2.3 修正」這樣的範圍，或一份版本清單；
- **已修正的版本**（若有）：升級到其中一個；
- **嚴重程度**：回報者有提供時，為一個 CVSS 向量；
- **參考資料與致謝**：修正、回報，以及同一缺陷的其他 id。

撤銷的公告仍會列出，並標示為已撤銷，`nabi audit` 會略過它。

整份清單也是一個供其他工具使用的 API：`GET https://packages.nabi-lang.org/api/v1/advisories?format=json` 以 OSV JSON 提供所有公告，`/api/v1/packages/<name>/advisories` 則提供單一套件的公告。欄位請見 [API 參考](https://packages.nabi-lang.org/api)。

## 回報漏洞

在某個套件中發現漏洞？請先私下告知它的擁有者，他們儲存庫的安全性政策會說明方式。如果他們沒有回應，或者缺陷在登錄庫或工具鏈中，請寫信到 [security@nabi-lang.org](mailto:security@nabi-lang.org)。

套件的擁有者可以透過 API 為它起草公告（用具有 `owners` 權限範圍的帳戶權杖呼叫 `POST /api/v1/advisories`）；登錄庫的維護者會審查並發布它，發布時套件的每位擁有者都會收到一封郵件。
