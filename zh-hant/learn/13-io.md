# 13. 檔案與網路 IO

本章說明程式如何與外部世界溝通。檔案與目錄、路徑、標準 IO、環境變數、子行程（child process），以及 TCP / UDP 通訊端（socket），都在 `std` 裡。

IO 隨時可能失敗，所以幾乎每個函式都是 `throws (IoError)`。本章處處用到[第 10 章](10-errors.html)的 `try` / `catch`。範例寫成 `fn main() throws (IoError)`，表明哪些地方可能失敗；一般的 `fn main()` 也能使用 `try`，離開它的錯誤會被印出，並以結束碼 1 結束程式。

## 讀寫檔案

最簡單的方式是 `fs::write` 與 `fs::read_to_str`。這兩個函式會替你開啟和關閉檔案。下面的範例在 `env::temp_dir()` 底下建立一個目錄，在裡面操作，最後再把它刪除。

```nabi
use std::fs;
use std::env;
use std::process;
use core::io::IoError;

fn main() throws (IoError) {
    let dir = env::temp_dir() / f"nabi_learn13_{process::id()}";
    try fs::create_dir_all(dir / "notes" / "2026");

    try fs::write(dir / "hello.txt", "first line\nsecond line\n");
    let text = try fs::read_to_str(dir / "hello.txt");
    print(text);
    println(f"{text.lines().count()} lines");

    try fs::read_to_str(dir / "nope.txt") catch e {
        println(f"error kind: {e.kind():?}");
        ""
    };

    try fs::remove_dir_all(dir);
    println(f"exists after cleanup: {fs::exists(dir)}");
}
```

```output
first line
second line
2 lines
error kind: NotFound
exists after cleanup: false
```

`IoError` 帶有一個 `kind()`（`NotFound`、`PermissionDenied`、`TimedOut`，以及其他行程占用該檔案或裝置時的 `ResourceBusy` 等），還有一則人看得懂的訊息。要依錯誤種類分支，就比較 `kind()`。

路徑引數接受 `str` 或 `Path`（`AsPath` trait），所以 `"a.txt"` 和 `dir / "a.txt"` 都能傳入。

`fs::lines(path)` 逐行讀取檔案，在讀第一行時開啟檔案，讀完最後一行後關閉：`try for line in fs::lines(p) { .. }`。`fs::glob(pattern)` 列出符合樣式的路徑並排序：名稱內可用 `*` 與 `?`，`[a-z]` 表示一組字元，`**` 這個路徑元件則代表任意層數的目錄。

```nabi
use std::{env, fs, process};

fn main() {
    let dir = env::temp_dir() / f"nabi_learn13_glob_{process::id()}";
    try fs::create_dir_all(dir / "src");
    try fs::write(dir / "a.txt", "one\ntwo\n");
    try fs::write(dir / "src" / "b.txt", "three\n");
    try for line in fs::lines(dir / "a.txt") { println(line); }
    for p in try fs::glob(f"{dir}/**/*.txt") {
        println(p.strip_prefix(dir) ?? p);
    }
    try fs::remove_dir_all(dir);
}
```

```output
one
two
a.txt
src/b.txt
```

## `File` 與開啟函式

要逐步寫入或逐行讀取，就直接開啟一個 `File`。使用 `using` 區塊時，檔案會在區塊結束時關閉；`using f = ..;` 這種陳述式則在外層區塊結束時關閉檔案，如下面的 `show`。關閉檔案可能失敗，所以編譯器不會替你關閉：用 `using` 繫結它，或呼叫 `try f.close()`；留著沒關閉的 `File` 是編譯錯誤。每種開啟方式各有自己的函式，所以寫不出錯誤的組合：`File::open`（既有的檔案，除非傳入 `WriteOnly` 之類的 `Access`，否則唯讀）、`File::create`（建立或清空）、`File::create_new`（檔案已存在時失敗）、`File::open_or_create`，以及 `File::append`（不存在時建立，每次寫入都寫在結尾）。

```nabi
use std::fs;
use std::fs::File;
use std::env;
use std::process;
use std::path::Path;
use core::io::{IoError, BufReader};

fn show(log: Path) throws (IoError) {
    using r = BufReader::new(try File::open(log));
    try for line in r.lines() {
        println(f"> {line}");
    }
}

fn main() throws (IoError) {
    let log = env::temp_dir() / f"nabi_learn13_log_{process::id()}.txt";

    using f = try File::create(log) {
        try f.write_all("start\n");
    }
    using f = try File::append(log) {
        try f.write_all("more\n");
    }
    try show(log);
    try fs::remove_file(log);
}
```

```output
> start
> more
```

`File::create` 建立檔案或將其截斷，`File::open` 以唯讀方式開啟。讀取與寫入是 `io::Read` 和 `io::Write` 這兩個 trait 的方法，每個檔案不需要 `use` 就能使用。逐行讀取需要緩衝區，所以要把檔案包進 `io::BufReader`；關閉讀取器就會關閉檔案。若想沿用同一個名稱，就重新宣告：`let f = BufReader::new(f);` 會把檔案移入讀取器，只需要關閉讀取器。`lines()` 給出的每一行都不含換行字元，讀取錯誤會以擲回的方式結束迴圈，所以要寫成 `try for`。

`r.lines()` 是 `r` 的檢視（view）：它透過讀取器讀取資料，只能待在擁有 `r` 的那一方的作用域內。把它從函式回傳、在該作用域之外保留它，或在任務中擷取它，都是編譯錯誤（[E0139](../errors/E0139.html)），錯誤訊息會指出修正方式：

```text check=checks/E0139.nabi
error[E0139]: this returns a view of `r` out of `r`'s scope
  --> main.nabi:6:9
   |
 6 |         return r.lines();
   |         ^^^^^^
   |                --------- a view of `r` made here
   |
   = help: `r.lines()` reads through `r` and stays in its scope; use it there (`try r.lines().collect()`), or take the owning form `r.into_lines()`, which owns `r` and closes it with itself
```

移動 `r` 同樣會讓它的檢視失效：在 `let kept = r;`、以傳值方式接收 `r` 的呼叫、`[move r]`，或把 `r` 存進結構之後，先前由它建立的檢視就不能再用。先用完檢視，或改為移動持有形式（owning form）。

只為了一次借用它的呼叫而建立的讀取器或檔案，例如 `(try File::open(p)).read_to_str()` 或 `BufReader::new(try File::open(p)).lines()`，在呼叫之後就沒有擁有者，也就沒有人會關閉它。這是 [E0134](../errors/E0134.html)；請先繫結它：`using f = try File::open(p);`，再寫 `try f.read_to_str()`。

當這些行必須離開作用域時，就使用持有形式 `r.into_lines()`。它回傳一個 `io::Owned`，這個值接收讀取器，在你關閉這些行時（`try ls.close()`）一併關閉讀取器，可用 `into_inner()` 把讀取器交還，也可以被回傳或移入任務（讀取器是 `Send` 時，它也是 `Send`）：

```nabi
use std::fs;
use std::fs::File;
use std::env;
use std::process;
use core::io::{IoError, BufReader, Lines, Owned};

// The lines own the reader, so they can leave the function.
fn open_lines(path: str) throws (IoError) -> Owned<Lines<BufReader<File>>, BufReader<File>> {
    BufReader::new(try File::open(path)).into_lines()
}

fn main() throws (IoError) {
    let log = env::temp_dir() / f"nabi_learn13_owned_{process::id()}.txt";
    try fs::write(log, "start\nmore\n");

    let ls = try open_lines(log.as_str());
    try for line in ls {
        println(f"> {line}");
    }
    try ls.close();                  // closes the reader and the file
    try fs::remove_file(log);
}
```

```output
> start
> more
```

同樣的配對還有 `bytes` / `into_bytes`、`split` / `into_split`、`take` / `into_take`、非同步的 `lines_async` / `into_lines_async` 與 `bytes_async` / `into_bytes_async`，以及監聽器的 `incoming` / `into_incoming`。`a.chain(b)` 一律擁有兩個讀取器並將兩者都關閉，`into_inner()` 會交還這一對讀取器。`take` 檢視沒有 `into_inner()`；之後若要取回讀取器，請使用 `into_take` 及其 `into_inner()`。

## 目錄與 `Dir` 能力

`fs::walk` 以深度優先、依名稱順序走訪目錄。`fs::read_dir` 只列出一層。讀取目錄時，任何一個項目都可能失敗，所以兩者都用 `try for` 逐一處理。

`Dir` 有點特別：`Dir` 控制代碼是一種**能力**（capability）。`Dir::root()` 是可用一般路徑操作的預設控制代碼，從它用 `open_dir` 開啟的 `Dir` 只能存取該目錄之內。試圖以絕對路徑或 `..` 逃出的操作都會被拒絕。處理不受信任的路徑（使用者輸入、封存檔內的名稱）時，這是一道安全網。

```nabi
use std::fs;
use std::fs::Dir;
use std::env;
use std::process;
use core::io::IoError;

fn main() throws (IoError) {
    let base = env::temp_dir() / f"nabi_learn13_dir_{process::id()}";
    try fs::create_dir_all(base / "notes" / "2026");
    try fs::write(base / "notes" / "a.md", "# a");
    try fs::write(base / "notes" / "2026" / "b.md", "# b");

    try for e in fs::walk(base) {
        let rel = e.path().strip_prefix(base) ?? e.path();
        if rel.as_str() != "" { println(f"{rel} dir={e.is_dir()}"); }
    }

    using d = try Dir::root().open_dir(base / "notes") {
        println(f"inside: {d.exists("a.md")}");
        try d.open("../../escape.txt").close() catch e { println(f"refused: {e.kind():?}"); };
        try d.open("/etc/hosts").close() catch e { println(f"refused: {e.kind():?}"); };
    }

    try fs::remove_dir_all(base);
}
```

```output
notes dir=true
notes/2026 dir=true
notes/2026/b.md dir=false
notes/a.md dir=false
inside: true
refused: PermissionDenied
refused: PermissionDenied
```

`create_dir`、`remove_file`、`remove_dir`、`rename`、`copy` 與 `metadata` 也都同時提供自由函式和 `Dir` 方法兩種形式。

## 路徑：`Path`

`std::path::Path` 是 UTF-8 路徑。和 Python 的 `pathlib` 一樣，用 `/` 運算子串接路徑。路徑不一定有上層目錄或副檔名，所以這些方法回傳 `T | none`。

```nabi
use std::path::Path;

let p = Path::new("/home/nabi/src/main.nabi");
println(f"parent:    {p.parent() ?? Path::empty()}");
println(f"file name: {p.file_name() ?? "-"}");
println(f"stem:      {p.file_stem() ?? "-"}");
println(f"extension: {p.extension() ?? "-"}");
println(f"absolute:  {p.is_absolute()}");

let q = Path::new("docs") / "guide" / "intro.md";
println(f"joined:    {q}");
println(f"swapped:   {q.with_extension("html")}");
println(f"normal:    {Path::new("a/./b/../c").normalize()}");
for c in q.components() { print(f"[{c.as_str()}]"); }
println("");
```

```output
parent:    /home/nabi/src
file name: main.nabi
stem:      main
extension: nabi
absolute:  true
joined:    docs/guide/intro.md
swapped:   docs/guide/intro.html
normal:    a/c
[docs][guide][intro.md]
```

`normalize` 只整理字串；`canonicalize` 則會查詢檔案系統，連符號連結也一併解析。

## 標準 IO 與環境

`print` 輸出時不加換行，`eprint` / `eprintln` 則寫到標準錯誤；需要緩衝或明確的寫入時，使用 `io::stdout()` / `io::stderr()`。`io::input("Your name? ")` 會寫出提示文字、排清輸出，並回傳下一行（不含換行字元），輸入結束時回傳 `none`，和 Python 的 `input` 一樣；`io::read_line()` 做同樣的事，只是沒有提示文字；要讀取每一行，寫 `try for line in io::stdin().lines()`。`io` 模組以及 `Read` / `Write` trait 不需要 `use`。

```nabi build
use core::io::IoError;

fn main() throws (IoError) {
    let out = io::stdout();
    try out.write_all("Your name? ");
    try out.flush();
    match try io::read_line() {
        line: str => println(f"Hello, {line.trim()}!"),
        none => println("(no input)"),
    }
    try io::stderr().write_all("bye\n");
}
```

命令列引數與環境變數在 `std::env` 裡。`env::args()` 的第 0 個元素是執行檔的路徑。變數未設定時，`env::var` 會擲回 `VarError`。

```nabi
use std::env;

let args = env::args();
println(f"{args.len()} arg(s)");

unsafe { try! env::set_var("NABI_GREETING", "annyeong"); }
println(try env::var("NABI_GREETING") catch _ { "unset" });
unsafe { try! env::remove_var("NABI_GREETING"); }
println(try env::var("NABI_GREETING") catch e { f"error: {e}" });

let mine = env::vars().filter(|kv| kv.0.starts_with("NABI_GREETING")).count();
println(f"matching vars: {mine}");
println(f"temp is absolute: {env::temp_dir().is_absolute()}");
```

```output
1 arg(s)
annyeong
error: environment variable not found
matching vars: 0
temp is absolute: true
```

`set_var` 與 `remove_var` 是 `unsafe`，而且會擲回錯誤。Nabi 自己的 `env` 函式共用一把鎖，但無法阻止 C 程式碼在同一時間讀取環境，所以請在產生執行緒之前就完成修改。名稱為空，或含有 `=` 或 NUL 時，會擲回 `IoError`（`InvalidInput`）。若只想替某一個子行程設定變數，請使用 `Command::env`，它不需要 `unsafe`。

## 子行程

`process::Command` 用來執行另一個程式。用建構器方法設定引數、環境與工作目錄，再以下列其中一種方式執行：`output()`（等待結束並收集 stdout / stderr）、`status()`（只取結束狀態），或 `spawn()`（不等待，直接回傳 `Child`）。

```nabi
use std::process::Command;
use core::io::IoError;

fn main() throws (IoError) {
    let out = try Command::new("echo").args(["hello", "from", "echo"]).output();
    print(try str::from_utf8(out.stdout) catch _ { "" });
    println(f"success: {out.status.success()}");

    let st = try Command::new("sh").args(["-c", "exit 3"]).status();
    println(f"code: {st.code() ?? -1}");

    try Command::new("no-such-program").status() catch e {
        println(f"spawn failed: {e.kind():?}");
    };
}
```

```output
hello from echo
success: true
code: 3
spawn failed: NotFound
```

`out.stdout` 是位元組（`List<u8>`），所以要用 `str::from_utf8` 轉成文字。如果只需要文字形式的輸出，`process::run("git", ["status"])` 會執行程式直到結束，並回傳它的 stdout；結束碼不為零時會擲回 `ExitStatusError`，用它的 `status()` 與 `stderr()` 可以得知發生了什麼事。被訊號終止的行程，其 `code()` 為 `none`；在 Linux 和 macOS 上，`st.signal()` 會指出是哪個訊號（`Signal::Kill` 等）。建構器方法會回傳修改過的副本，被呼叫的指令本身保持不變，所以 `let base = Command::new("git"); let log = base.arg("log");` 之後，`base` 不含 `log`。

子行程的串流導向何處，由 `Stdio` 決定。使用 `Stdio::Piped` 時，用 `take_stdin()`、`take_stdout()` 或 `take_stderr()` 從 `Child` 取出各個管道（若該串流沒有接管道或已被取走，則為 `none`）；取走的一方擁有它，也負責關閉它。移入 `Stdio::File(f)` 的 `File` 屬於該指令：執行時會關閉你的那一份，所以移動之後 `f` 就不存在了，子行程則保有它自己的一份。帶有 `Stdio::File` 的指令只能執行一次；要再次執行，就給它一個新的檔案（`f.try_clone()`）。`Stdio::File` 值也只有一個擁有者：把它交給兩個指令，或交給同一個指令的兩個串流（`.stdout(s).stderr(s)`），都是錯誤（[E0133](../errors/E0133.html)）；請各給一個自己的 `Stdio::File(try f.try_clone())`。`Stdio::Inherit`、`Null` 與 `Piped` 不持有任何東西，可以重複使用。從未交給任何指令的 `Stdio::File` 必須關閉（`try s.close()`），和它的 `File` 一樣。

`Child` 只有一個擁有者，也就是等待它的那一方。若要在該擁有者等待時從別處停止子行程（逾時、關機），就取得 `child.handle()`：這是一個 `ChildHandle`，其他執行緒或任務可以用它對子行程呼叫 `kill()` 或 `send_signal(..)`。它不擁有任何管道，也不負責等待；`h.id()` 給出子行程的行程 ID，子行程結束之後，透過它送出的訊號不會有任何作用。

## TCP 與 UDP

`std::net` API 預設是阻塞式的。下面的範例在同一個程式裡執行伺服器和用戶端。繫結到連接埠 `0` 會讓作業系統挑選一個空閒的連接埠，`local_addr()` 則回報實際的位址。伺服器在一個執行緒上接受一個連線，並把收到的文字轉成大寫後回傳。

位址可以是 `SocketAddr`、`"host:port"` 文字（名稱會被查詢解析）、`(IpAddr, u16)` 配對，或位址串列：`TcpStream::connect`、`TcpListener::bind` 與 `UdpSocket::bind` 接受任何實作 `ToSocketAddrs` 的值，並依序嘗試這些位址。`net::tcp_connect`、`net::tcp_listen` 與 `net::udp_bind` 是相同呼叫的自由函式版本。

通訊端的關閉可能失敗，所以每個通訊端都由它的擁有者關閉，用 `try s.close()` 或 `using`；留著通訊端未關閉的程式，編譯器會拒絕編譯。

```nabi
use std::net::{TcpListener, TcpStream, Shutdown};
use core::io::IoError;
use std::thread;

fn main() throws (IoError) {
    let listener = try TcpListener::bind("127.0.0.1:0");
    let addr = try listener.local_addr();

    let server = thread::spawn(|| {
        let (conn, _) = try! listener.accept();
        let msg = try! conn.read_to_str();
        try! conn.write_all(msg.to_uppercase());
        try! conn.close();
        try! listener.close();       // the thread owns the listener now
        msg.len()
    });

    let client = try TcpStream::connect(addr);
    try client.write_all("hello, socket");
    // Half-close: the server's read_to_str sees the end.
    try client.shutdown(Shutdown::Write);
    println(f"reply: {try client.read_to_str()}");
    try client.close();
    println(f"server read {try! server.join()} bytes");
}
```

```output
reply: HELLO, SOCKET
server read 13 bytes
```

若要從兩個執行緒或任務同時讀寫同一個連線，就用 `split()` 把它分成 `ReadHalf` 與 `WriteHalf`。每一半各自擁有自己的方向，並由自己的擁有者關閉。關閉寫入的一半，會像 `shutdown(Shutdown::Write)` 一樣讓對方看到串流結束，而讀取的一半則繼續讀取回覆；第二個一半關閉時，通訊端也隨之關閉。在任一半上呼叫 `shutdown(Shutdown::Both)`，會把通訊端的兩個方向都關閉，並喚醒在另一半上阻塞的讀取。`r.unsplit(w)` 會交還原本的連線。`UnixStream` 與 TLS 連線也以同樣的方式分割。

```nabi
use std::net::{TcpListener, TcpStream, WriteHalf};
use core::io::IoError;
use std::thread;

fn send(w: WriteHalf<TcpStream>) -> i32 {
    try! w.write_all("hello, halves");
    try! w.close();                  // the server's read_to_str sees the end
    0
}

fn main() throws (IoError) {
    let listener = try TcpListener::bind("127.0.0.1:0");
    let addr = try listener.local_addr();
    let server = thread::spawn(|| {
        let (conn, _) = try! listener.accept();
        try! listener.close();
        let msg = try! conn.read_to_str();
        try! conn.write_all(msg.to_uppercase());
        try! conn.close();
        0
    });

    let (r, w) = (try TcpStream::connect(addr)).split();
    let writer = thread::spawn(|| send(w));
    println(f"reply: {try r.read_to_str()}");
    try r.close();                   // the socket closes with the second half
    _ = try! writer.join();
    _ = try! server.join();
}
```

```output
reply: HELLO, HALVES
```

UDP 不建立連線，直接交換資料包（datagram）。`recv_from` 回傳收到的位元組數，以及傳送端的位址。

```nabi
use std::net;
use core::io::IoError;

fn main() throws (IoError) {
    let a = try net::udp_bind("127.0.0.1:0");
    let b = try net::udp_bind("127.0.0.1:0");
    try b.send_to("ping", try a.local_addr());

    let buf = List::filled(64, 0u8);
    let (n, from) = try a.recv_from(buf);
    println(f"got {n} bytes: {try str::from_utf8(buf[0:n]) catch _ { "?" }}");
    println(f"from b: {from == (try b.local_addr())}");
    try a.close();
    try b.close();
}
```

```output
got 4 bytes: ping
from b: true
```

在這些之下是 `net::Socket`，也就是作業系統所看到的通訊端：由你選擇網域、通訊端種類與協定，設定 `set_reuse_address` 或 `set_only_v6` 之類的選項，並自行呼叫 `bind` / `listen` / `connect`。接著再由 `TcpListener::from(s)`（或 `TcpStream::from`、`UdpSocket::from`）接手。

```nabi
use std::net::{Socket, Domain, SocketType, Protocol, TcpListener};
use core::io::IoError;

fn main() throws (IoError) {
    let s = try Socket::new(Domain::Ipv4, SocketType::Stream, Protocol::TCP);
    try s.set_reuse_address(true);
    try s.bind(try! "127.0.0.1:0".parse());
    try s.listen(16);
    let l = TcpListener::from(s);
    println(f"listening on port 0: {(try l.local_addr()).port() > 0}");
    try l.close();
}
```

```output
listening on port 0: true
```

## 非同步 IO：`*_async`

在任務中（請見[第 12 章](12-concurrency.html)），不使用阻塞式呼叫，而是 `await` 同名但帶有 `_async` 後綴的版本。對通訊端來說，等待期間只有該任務暫停，執行緒會去執行其他任務。一般檔案沒有作業系統層級的非同步等待支援，所以呼叫會在另一個執行緒上執行，任務則等待結果。錯誤的擲回方式與同步版本完全相同。

```nabi
use std::fs;
use std::fs::File;
use std::net;
use std::net::{TcpStream, Shutdown};
use std::env;
use std::process;

let path = env::temp_dir() / f"nabi_learn13_async_{process::id()}.txt";
try! await fs::write_async(path, "written in a task");
let f = try! await File::append_async(path);
try! await f.write_all_async(", then appended");
try! await f.close_async();
println(try! await fs::read_to_str_async(path));
try! await fs::remove_file_async(path);

let l = try! net::tcp_listen("127.0.0.1:0");
let addr = try! l.local_addr();
let server = task::spawn(async {
    let (conn, _) = try! await l.accept_async();
    try! await l.close_async();
    let got = try! await conn.read_to_end_async();
    try! await conn.close_async();
    got.len()
});
let c = try! await TcpStream::connect_async(addr);
try! await c.write_all_async("twelve bytes");
try! await c.shutdown_async(Shutdown::Write);
try! await c.close_async();
println(f"server got {await server} bytes");
```

```output
written in a task, then appended
server got 12 bytes
```

串流相關的呼叫來自 io trait。`AsyncRead`、`AsyncWrite`、`AsyncSeek` 與 `AsyncClose` 為每個檔案、通訊端、TLS 連線和子行程管道，以及以它們為約束的你自己的程式碼，提供 `read_async`、`write_all_async`、`flush_async`、`seek_async` 與 `close_async`。`close_async` 和 `close` 一樣會關閉該值，所以也算是關閉了它。只有不屬於串流讀寫的操作才是該型別自己的方法：`connect_async`、`accept_async`、`shutdown_async`，以及子行程的 `Child::wait_async`、`Command::output_async` 與 `Command::status_async`。非同步方法會更新被呼叫的那個值，所以要在呼叫處就 `await` 它（[第 12 章](12-concurrency.html)）。

連線數以千計時，任務遠比每個連線一個執行緒輕量。如果工具只有少數幾個連線，阻塞式 API 比較簡單。

## 小結

- 整個檔案：`fs::read_to_str` / `fs::write`。逐步處理：`File` + `using`，依需要的方式選用開啟函式（`open`、`create`、`create_new`、`open_or_create`、`append`）。
- `Dir` 是一種能力。已開啟的 `Dir` 之外的一切（絕對路徑、`..`）都會以 `PermissionDenied` 拒絕。
- 用 `Path` 與 `/` 運算子組合路徑；可能不存在的部分會以 `T | none` 回傳。
- 與外部環境互動時，使用 `io::stdin/stdout/stderr`、`env::args/var/temp_dir`、`io::input`，以及 `process::run` / `process::Command`。`fs::lines` 與 `fs::glob` 用來讀取各行和比對路徑。
- TCP / UDP：以 `ToSocketAddrs` 為基礎的 `TcpListener::bind` / `TcpStream::connect` / `UdpSocket::bind`（或 `net::tcp_listen` / `net::tcp_connect` / `net::udp_bind`）；需要各種選項時用 `net::Socket`。使用連接埠 `0` 時，由作業系統挑選。每個通訊端都要關閉：`try s.close()` 或 `using`。要從兩個執行緒或任務讀寫同一個連線，就用 `split()` 分割它。
- 在任務中，`await` 各個 `*_async` 版本；用 `try await s.close_async()` 關閉。
- `r.lines()` 與其他配接器是只能待在 `r` 作用域內的檢視；`r.into_lines()` 與其他 `into_` 形式擁有讀取器，可以離開作用域。
