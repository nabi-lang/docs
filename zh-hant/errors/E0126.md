# E0126: 連結失敗

程式通過了型別檢查，但連結失敗：連結器回報了錯誤，或找不到原生函式庫。`nabic check` 在連結之前就會停止，所以連結失敗只會在建置時出現（`nabi build`、`nabi run`、`nabic build`）。常見的原因是 `extern` 區塊中宣告的函式所在的函式庫沒有連結：libc 和 libm 預設會連結，其他函式庫都需要 `#[link]`（[6.2.3](../spec/refs-lang/006-meta-system/602-built-in-attributes.html#623-link-指定外部函式庫)）。請檢查 `-L` 目錄和 `#[link]` 的名稱。

這個程式呼叫了 zlib 的函式，卻沒有連結 zlib：

```nabi norun
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

在 macOS 上，`nabic build` 會印出以下內容（已縮短；在其他平台上，符號開頭沒有 `_`）：

```text
   Compiling main (.)
error[E0126]: the link failed:
undefined symbol: _compressBound
>>> referenced by .../module0.o
...
```

`compressBound` 在 zlib 中。連結 zlib：

```nabi
#[link("z")]
extern "C" {
    fn compressBound(len: u64) -> u64;
}

println(f"{unsafe { compressBound(1000) }}");
```

```output
1013
```
